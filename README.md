# @utk09/ui-observability

Structured logging and UI observability for browsers, embedded webviews and OpenFin containers. The library imports no framework.

The library batches records and sends them over HTTP as OTLP/JSON. It stores a batch that fails to send, and sends it again later. When the page closes, the library sends the records that are left. Iframes, workers and OpenFin windows share one sender through the bus. A log call never throws.

> **Status: early development.** A minor release can change a public API. Pin the exact version.

## Installation

Use one command for your package manager. Each command saves an exact version.

```bash
# npm
npm install --save-exact @utk09/ui-observability

# pnpm
pnpm add --save-exact @utk09/ui-observability

# Yarn
yarn add --exact @utk09/ui-observability
```

The package has an ES module entry and a CommonJS entry. Each entry has its own type declarations.
The types work with `moduleResolution` set to `NodeNext` or `Bundler`. They also work with `skipLibCheck: false`.
Use one module format in one application. The two entries are separate copies with separate state and separate types.

### Peer Dependencies

Each peer is optional. The library has no runtime dependency.

Install `@rrweb/record` (`^2`) for the session replay, and set `replay.loader`. See [Session replay](#session-replay).

Install `web-vitals` (`^4 || ^5 || ^6`) for `capture.webVitals`, and set `capture.webVitals.loader`. The object turns the capture on. Without the loader, the library reports `config.invalid`. LCP, CLS and INP then stay off, and the navigation timing continues.

```ts
configure({
  endpoint: "https://telemetry.example.com/v1/logs",
  capture: {
    webVitals: { loader: () => import("web-vitals") },
  },
});
```

Install `@opentelemetry/api` (`^1`) to put records on the traces of your spans. Set `otelLoader` to load it. Without `otelLoader`, OTel is off. The library then makes its own `trace_id`.

The library never imports a peer by name. A missing peer cannot break your bundler or your dev server.

```ts
configure({
  endpoint: "https://telemetry.example.com/v1/logs",
  otelLoader: () => import("@opentelemetry/api"),
});
```

## Quick Start

Call `configure()` one time at startup, before the first log call.

```ts
import { configure, getLogger } from "@utk09/ui-observability";

configure({
  endpoint: "https://telemetry.example.com/v1/logs",
  serviceName: "equities-blotter",
  serviceVersion: "2.4.1",
  environment: "production",
});

const log = getLogger("blotter.grid");

log.info("grid ready");
log.logAction("ORDER_SUBMIT", { orderId: "ORD-1001", qty: 100 });
log.error("pricing call failed", caughtError);
```

- `configure()` is idempotent. A later call updates an unlocked runtime singleton in place. Delivery/identity changes require `rotateSecurityContext()` by default. You cannot change the `storage` section, `identity`, `correlation`, `limits`, `journey.maxAgeMs`, `profiler.maxProbes`, `bus.mode` or `bus.openFinRole` after startup. You cannot change `batching` or `retention` after the delivery stack loads. The library reports that change and ignores it. [Settings that are fixed after startup](docs/production-recipes.md#settings-that-are-fixed-after-startup) gives the exact rule for each key.
- Call `configure()` from one context in each document. A second call changes `service.name` on the records of every other context. In a composed page, the shell calls `configure()`. Each microfrontend uses its own namespace.
- You can call `getLogger()` at module top level, before `configure()`. The logger finds the runtime on its first write.
- Before the first `configure()` call that works, the runtime is unconfigured. `getHealth().status` is `"unconfigured"`.
  - A log call does not throw. It prints to the console with the default `consoleOutput` settings. The default console is off.
  - The record waits in memory, in the hold buffer. `buffering.maxHeldRecords` limits that buffer.
  - The library installs no capture. It starts no bus and no sender. It sends nothing.
  - The ids stay in memory. The library writes nothing to `localStorage` or `sessionStorage`.
  - Context attributes, breadcrumbs, journeys and trace calls work in memory.
  - A frame or a worker that you register joins the bus when the runtime starts.
  - `rotateSecurityContext()` rejects. Call `configure()` first.
  - A `newSession()` call starts a new session. The runtime keeps that session when it starts.
- The first `configure()` call that works starts the runtime. That call can set each setting that is fixed after startup.
  - The held records then get the `processors`, the `redact` hook and the identity of that call. Then they go out.
  - The `minLevel`, `minLevels`, sampling, `limits` and `page.url` rules of that call also apply to the held records. A query that the default rule removed from `page.url` does not come back.
  - The console does not print a held record a second time.
  - The library removes the breadcrumbs of log calls from before the start, because no hook saw them. The breadcrumbs of `addBreadcrumb()` stay.
  - With `enabled: false` in that call, the runtime starts at the first `enabled: true`. `onDrop` reports the held records with `disabled`. Until then, the library writes nothing to storage and starts no bus and no sender.
- Call `configure()` in the parent before child frames load. A child frame or a worker that starts before the parent runtime starts gets no owner.
  - After the handshake timeout, the child becomes its own sender. It then uses only its own config and its own `redact`.
  - The timeout is 1,500 ms in a same-origin frame or in a worker. A cross-origin frame tries 3 times, so its timeout is 4,500 ms.
- Call `setConfigurationLocked(true)` after `configure()`. A lock before the first `configure()` refuses that call too, and the runtime does not start.
- An app that never calls `configure()` gets console output only.
- If the first `configure()` call cannot read its options, the runtime stays unconfigured. It writes a console warning and reports `config.invalid`.
  - The library drops each held record and each new record. It writes no id to storage.
  - A later call without `redact` adds its settings. The library continues to drop each record.
  - The first later call that sets `redact` to a function or `null` starts the runtime.
- After `shutdown()`, logging does nothing until the next `configure()`. `getHealth()` still reads the stopped runtime.

### Console Only (No Network)

Set `endpoint: null`. The library sends nothing. It prints records to the console only.

```ts
configure({
  endpoint: null,
  serviceName: "skardela",
  identity: "memory",
  storage: { backend: "none" },
  bus: { mode: "off" },
  consoleOutput: import.meta.env.DEV ? "DEBUG" : "WARN",
});
```

- `endpoint: null` loads no transport, no storage and no exit flush. It reports no diagnostic.
- `identity: "memory"` writes no key to `localStorage` or `sessionStorage`.
- `consoleOutput` and `minLevel` are independent. `consoleOutput` sets what the library prints. `minLevel` sets what the library sends.
- The console output does not depend on the bus or the endpoint.
- With a `redact` hook, the console shows only what `redact` returns. A record that a processor or `redact` drops prints no line. With `redact` or `processors`, a record below `minLevel` or outside the sample also goes through them before the console prints it. Without hooks, such a record shows its message, payload and error as given.

### Console Output

Each console line has the form `[namespace][LEVEL] message payload`:

```text
[app.puzzle-page][INFO] The puzzle page loaded {puzzleId: 'colour-binary-0006', difficulty: 'easy'}
```

The namespace and the level each have a color. To change the colors, use the object form of `consoleOutput`:

```ts
configure({
  consoleOutput: {
    level: "DEBUG",
    styles: {
      namespace: "color:#888",
      INFO: "color:#0a7;font-weight:bold",
      WARN: "color:#c80;font-weight:bold",
    },
  },
});
```

- Each style is a CSS string. A browser applies it with `%c`. Node prints the text without the style.
- A style can set the text color and the background together. This example shows the level as a badge:

  ```ts
  configure({
    consoleOutput: {
      styles: {
        INFO: "color:#fff;background:#1e6fd9;padding:0 4px;border-radius:3px",
        ERROR: "color:#fff;background:#d32f2f;padding:0 4px;border-radius:3px",
      },
    },
  });
  ```

- The style keys are `namespace`, `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR` and `FATAL`. A key that you do not set keeps its style.
- The default namespace color is gray. The default levels are gray for `TRACE` and `DEBUG`, blue for `INFO`, orange for `WARN`, and red for `ERROR` and `FATAL`.
- A later `configure({ consoleOutput: "WARN" })` changes the level. The styles stay.
- A later `configure({ consoleOutput: { styles } })` changes the styles. The level stays. A console that is off stays off.

### Custom Transport

Set `transport` to send batches through a channel of your app, for example an API client with token refresh, a WebSocket, Electron IPC or an OpenFin channel. With `transport`, `endpoint` is optional.

```ts
configure({
  serviceName: "equities-blotter",
  transport: async (request) => {
    const response = await apiClient.post("/telemetry", request.body, {
      headers: { "Content-Type": request.contentType, "X-UiObs-Batch-Id": request.batchId },
    });
    const retryAfterSeconds = Number(response.headers["retry-after"]);
    return { status: response.status, retryAfterMs: retryAfterSeconds * 1000 };
  },
  // Optional. It runs while the page closes, so it must not wait for a promise.
  transportOnExit: (request) => navigator.sendBeacon("/telemetry", request.body),
  // Network capture must not log the requests of your transport.
  capture: { ignoreUrls: ["/telemetry"] },
});
```

- The library keeps batching, retry, storage, splitting and the exit flush.
- The status code that you return has the meaning of the ingest contract. `2xx` accepts the batch. `413` splits it. `429` and `503` throttle. `408` and `5xx` retry. Each other code drops the batch.
- A rejected promise counts as a network error. The library sends the batch again later. A call that does not settle in 15 seconds counts as a timeout.
- The library does not compress `request.body`. Compress it in your transport if necessary.
- `request.records` holds the built records after `redact`. Do not change them, because the retry engine can send them again.
- `request.kind` is `"metrics"` for a batch of metric records when `metricsEndpoint` is set. `request.body` is then an OTLP `ExportMetricsServiceRequest`. Send it to your metrics endpoint.
- `request.kind` is `"traces"` for a batch of span records. `request.body` is then an OTLP `ExportTraceServiceRequest`. Send it to your traces endpoint. Each other batch has the kind `"logs"`.
- Without `transportOnExit`, the last batch goes to the emergency queue when the page closes. The next page load sends it.
- With `storage: { backend: "none" }`, the next page load cannot keep that batch. Set `transportOnExit`, or the library loses the last batch.
- The library ignores a `retryAfterMs` or a `maxBytes` that is not a finite number. It uses 0 for a negative value.
- `request.signal` aborts at `shutdown()` and at a rotation. Check it to cancel your work. A stored batch of that request stays in storage.
- Return the `Date` header of a `2xx` answer in `date`. The library then computes `uiobs.clock_offset_ms`.
- After the delivery stack loads, you cannot add or remove `transport`. You can replace it with another function.
- Network capture skips a request that your transport starts before its first `await`. Put your telemetry URL in `capture.ignoreUrls` too. A request after an `await` is outside that scope.
- Without that URL in `capture.ignoreUrls`, each send records a value of the `http.client.request.duration` histogram. That value causes the next send, and the sends do not stop. Network capture reports `capture.transport_request` one time when it sees a request during a transport call.

### Worker transport

The app creates a dedicated module worker. Configure its factory at startup.

```ts
configure({
  endpoint: "https://ingest.example/v1/logs",
  serviceName: "orders",
  transportWorker: () =>
    new Worker(new URL("./transport.worker.ts", import.meta.url), { type: "module" }),
});
```

In `transport.worker.ts`:

```ts
import { serveTransportWorker } from "@utk09/ui-observability";

serveTransportWorker();
```

The worker encodes OTLP or ECS, compresses the payload and sends HTTP requests. Record construction, privacy hooks, queue accounting, retry and storage stay on the main thread. The `headers` function also stays there. The worker receives only its resolved headers and built records after the privacy hooks.

- Return a fresh worker from each factory call. The library owns that worker until shutdown or rotation.
- Bundle and serve the worker script with the app. Its worker policy and CORS rules must permit the script and the ingest endpoint.
- Use the same exact library version in the worker and the page. A private transferred port carries a fixed protocol tag and that version.
- `serveTransportWorker()` installs its connection listener at once. It loads the worker delivery code after the connection. Its return value stops the service. Its optional `onDiagnostic` handler runs in the worker.
- One request deadline covers header resolution, transfer, encoding, compression and delivery. The main thread handles status codes, sampling rules and clock offset.
- A startup failure or a channel failure during a send switches that sender to HTTP. A worker that does not connect before the request deadline is a startup failure. A new factory or a rotation permits another worker. A timeout or network failure follows the normal retry policy.
- Hidden-page sends use the main HTTP keepalive path. The exit flush also stays on the main thread. It uses the same cached headers.
- `transport` takes precedence over `transportWorker`. A custom serializer runs on the main thread. Functions do not cross the worker channel.
- With isolation on, change the factory through `rotateSecurityContext()`. After the stack loads, `configure()` cannot add or remove `transportWorker`.
- The helper does not join the context bus. Node remains console-only.

The vanilla playground has links for the worker and main-thread paths. Verify both paths in a real browser before release.

### Testing

Use `createMemoryTransport()` to check what your code logs. It needs no network and no `fetch` mock.

```ts
import {
  configure,
  createMemoryTransport,
  flush,
  getLogger,
  shutdown,
} from "@utk09/ui-observability";

const memory = createMemoryTransport();

beforeEach(() => {
  configure({
    serviceName: "orders",
    transport: memory.transport,
    storage: { backend: "none" },
    bus: { mode: "off" },
    identity: "memory",
  });
});

afterEach(async () => {
  memory.clear();
  await shutdown();
});

it("logs the order submit", async () => {
  getLogger("orders.ticket").logAction("ORDER_SUBMIT", { orderId: "ORD-1" });
  await flush();

  expect(memory.records()).toContainEqual(expect.objectContaining({ body: "ORDER_SUBMIT" }));
});
```

- `records()` returns the records of each accepted batch. `batches()` returns each request, accepted or refused.
- `respondWith(status, retryAfterMs?)` sets the answer for each later batch. Use it to test a `413`, `429` or `500` answer. The default answer is `200`.
- `flush()` waits for startup. A record that you log directly after `configure()` is in the flushed batch.
- `flush()` waits 5000 ms at most. Assert on its result to find a record that did not go out, for example `expect(await flush()).toMatchObject({ status: "complete" })`.
- After `shutdown()`, each call does nothing until the next `configure()`.
- Set `storage: { backend: "none" }` in tests. Without it, `shutdown()` stores the unsent records, and the next test can receive them.

### Remote Sampling

With `sampling: { remote: true }`, the ingest server can change the sampling during an incident. You do not deploy the app again.

```http
X-UiObs-Sampling: {"v":1,"ttlMs":600000,"defaultRate":0.1,"rates":{"blotter.grid":1},"minLevel":"DEBUG"}
```

- The library reads the header only on a `2xx` answer to a batch that it sent. A custom transport returns the rules in `TransportResponse.sampling`, as text or as an object.
- `v` must be `1`. `ttlMs` is mandatory, from more than 0 to 3,600,000 (1 hour). After the TTL, the rules from `configure()` apply again.
- `rates` apply over the `configure()` rates. The other `configure()` rates stay. `defaultRate` applies only if the header has it.
- `minLevel` can only lower the level that the library sends. It does not change the console level.
- `minLevels` sets a level for each namespace prefix, for example `{"trading.ticks":"DEBUG"}`. A remote prefix wins over the remote `minLevel`. A remote level applies only when it is lower than the `configure()` level of the namespace. At most 100 prefixes.
- `sampling.remoteMaxRate` caps each remote rate. It also caps the records that a remote `minLevel` adds. Set it below 1 to limit the traffic that a compromised server can cause.
- The library rejects all the rules if one field is not valid, for example a rate outside 0 to 1, more than 100 `rates` or a header longer than 4096 characters. It reports `config.invalid`.
- The library keeps the rules in memory only. A reload uses the `configure()` rules until the next accepted batch.
- A child frame, a worker or an OpenFin view asks its owner for the rules at start and each 30 seconds. Set `sampling.remote: true` in each context.
- A frame accepts rules from a parent only if the parent origin is the page origin or is in `bus.trustedOrigins`. A page that embeds your app cannot lower `minLevel`.
- Under the default `bus.sourcePolicy: "registered"`, a parent sends rules only to a frame or a worker that it registered with the `sampling:read` permission.
- Each OpenFin view of one app can read the bus messages of the others. Load only trusted content into a view that has the `fin` API.

### Logging Methods

| Function                                  | Description                                                                                                                                                                                                    |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getLogger(namespace, options?)`          | Returns the cached logger for a namespace. With `options`, it returns a new logger that is not cached.                                                                                                         |
| `trace(msg, payload?)`                    | Logs a TRACE record.                                                                                                                                                                                           |
| `debug(msg, payload?)`                    | Logs a DEBUG record.                                                                                                                                                                                           |
| `info(msg, payload?)`                     | Logs an INFO record.                                                                                                                                                                                           |
| `warn(msg, payload?)`                     | Logs a WARN record.                                                                                                                                                                                            |
| `error(msg, err?, payload?)`              | Logs an ERROR record with the error and the breadcrumb trail.                                                                                                                                                  |
| `fatal(msg, err?, payload?)`              | Logs a FATAL record with the error and the breadcrumb trail.                                                                                                                                                   |
| `logAction(name, payload?)`               | Logs one user action.                                                                                                                                                                                          |
| `logEvent(name, payload?)`                | Logs one domain or lifecycle event.                                                                                                                                                                            |
| `counter(name, { unit? })`                | Gives a counter. `add(value, attrs?)` sums a value of 0 or larger in memory. The library sends one point for each attribute set at each interval.                                                              |
| `gauge(name, { unit? })`                  | Gives a gauge. `set(value, attrs?)` keeps the last value for each attribute set in memory. The library sends that value as one point at each interval.                                                         |
| `histogram(name, { unit?, boundaries? })` | Gives a histogram. `record(value, attrs?)` counts a value in buckets in memory. The library sends one point for each attribute set at each interval.                                                           |
| `measure(name, fn, attrs?)`               | Calls `fn` and times the call with a measure. A promise result ends the measure when it settles. A throw or a rejection gives the outcome `"error"`, and the caller gets the error. See [Measures](#measures). |
| `startMeasure(name, attrs?)`              | Times an operation with named phases. See [Measures](#measures).                                                                                                                                               |
| `profiler.probe(name, options?)`          | Gives a probe that times code spans with a small fixed cost. See [Profiler](#profiler).                                                                                                                        |
| `profiler.time(name, fn)`                 | Calls `fn` and times the call with the probe of the name. A promise result ends the span when it settles. See [Profiler](#profiler).                                                                           |
| `startReplay()`                           | Starts the session replay recorder. With `replay.requireConsent`, nothing records before this call. See [Session replay](#session-replay).                                                                     |
| `stopReplay()`                            | Stops the session replay recorder and drops each replay event that is not sent.                                                                                                                                |

The level methods give records with `log.type: "log"`. Records of the library itself have `log.type: "system"`. A logger has no metric method. Use `counter`, `gauge` or `histogram`. Each instrument drops a value that is not finite and reports `record.dropped_malformed`.

`counter` and `histogram` sum their values for `metrics.intervalMs`. `gauge` keeps the last value. Then each instrument sends one point for each attribute set. 1000 calls of `add(1)` give one point with the value 1000. With `metricsEndpoint`, a gauge point is an OTLP gauge, and a counter point is an OTLP sum. Sampling and `minLevel` do not drop a point. The console does not print it. Each instrument keeps at most 100 attribute sets in each interval. The values of more sets go to one set with `otel.metric.overflow: true`. Attribute values must be strings, finite numbers or booleans. The library drops an attribute key that starts with `metric.`. It also drops the keys that it sets on each record, for example `page.url` and `log.type`. The record limits do not cut the metric fields of a point, for example the bucket counts. `redact` cannot change them. On a point from a frame or a worker, the sender's `redact` can change `metric.name`, `metric.unit` and `metric.attribute_keys`. Do not use a user id or a URL as an attribute. Each value makes a new series in the backend. The default histogram boundaries are `[0, 5, 10, 25, 50, 75, 100, 250, 500, 750, 1000, 2500, 5000, 7500, 10000]`. The points of the open interval go out at `flush()`, at `shutdown()` and before the exit flush. `shutdown({ pending: "discard" })` drops them. A frame that forwards its records sends its points at the interval, at `flush()` and at `shutdown()` only.

### Measures

`startMeasure()` times an operation with named phases.

```ts
const measure = startMeasure("checkout", { tier: "gold" });
measure.phase("validate");
await validate();
measure.phase("payment");
await pay();
measure.end();
```

- `phase(name)` closes the open phase and starts the next phase. `end(outcome?)` closes the open phase and records the total. Later calls of the handle do nothing.
- Each phase goes into the histogram `ui.measure.phase.duration` with `measure.name` and `measure.phase`. The total goes into `ui.measure.duration` with `measure.name` and `measure.outcome`. Both are in milliseconds.
- The default outcome is `"ok"`. Each name, outcome and attribute set makes one series. Keep these values small in number.
- With `tracesEndpoint`, the measure is a span of kind INTERNAL with one child span for each phase. The outcome `"error"` marks the measure span and its open phase as failed.
- A shutdown drops a measure that has no end. With isolation, a new delivery identity also drops it.
- `measure(name, fn, attrs?)` calls `fn` in a measure with no phases. The measure ends when `fn` returns. If the result has a `then` function, the measure ends when the result settles. A throw or a rejection gives the outcome `"error"`. The caller gets the same error.

### Profiler

`profiler.probe()` gives a probe that times a span that runs very often, for example a grid transaction, a sort or a render. `startMeasure()` makes a handle for each operation. A probe is one handle for all spans of its name. The profiler code makes no object for a `begin()` and `end()` pair, except one timer at the first value of each interval. The clock read of the platform can make one, for example in Node.js. The library sends one summary record for each probe at each interval, not one record for each span.

```ts
configure({ profiler: { enabled: true } });

const probe = profiler.probe("grid.applyTransaction");

const token = probe.begin();
grid.applyTransaction(update);
probe.end(token);

// Add a duration from another source, in milliseconds.
probe.record(durationMs);

// Measure one span of each 10 spans.
const sort = profiler.probe("grid.sort", { sampleEvery: 10 });

// End the span after the next paint. A span longer than 16 ms adds a breadcrumb.
const render = profiler.probe("grid.render", { slowMs: 16 });
const renderToken = render.begin();
grid.render();
render.endAfterPaint(renderToken);

// Time one call of a function. A promise result ends the span when it settles.
const rows = await profiler.time("rows.fetch", () => fetchRows());

// A span that an await splits needs an async probe.
const load = profiler.probe("blotter.load", { async: true });
```

- The profiler is off by default. While it is off, `begin()` returns `-1`. A probe then reads no clock.
- A probe stays valid across `configure()` and `shutdown()`. An app can make a probe before `configure()`. The same name gives the same probe. The first options of a name stay. A call never throws.
- A probe sums its durations for `metrics.intervalMs`. The default is 10 seconds. Counters and histograms use the same interval. Then the library sends one `ui.profile.duration` histogram record for each probe with data. `flush()`, `shutdown()`, `newSession()` and the exit flush also send the open interval.
- A record has the count, the sum, the minimum, the maximum and the buckets. Its attributes are `profile.probe`, `profile.sample_every`, `profile.p50`, `profile.p90`, `profile.p99`, `profile.self_p99` and `profile.overhead_ns`. See [Profile Attributes](docs/attributes.md#profile-attributes).
- The library counts each duration in a bucket, in whole microseconds. Each power of two has 16 buckets. Below 16 microseconds, a bucket is 1 microsecond wide. Above that, a bucket is at most 6.25 percent wide. The minimum and the maximum are exact. A duration above approximately 67 seconds counts in the last bucket. A record has at most 100 buckets. For a wider range of durations, the library merges adjacent buckets in the record.
- `sampleEvery: n` measures one span of each `n` spans. The probe uses a counter, not a random number. A span that the probe does not measure reads no clock. Its `begin()` returns `-1`. `record()` uses the same counter. The count in the record is the count of measured spans. A backend multiplies it by `profile.sample_every` for an estimate of all spans.
- A record of a probe with nested spans also has `profile.self_p99`. The self time of a span is its duration without the durations of the measured spans inside it. The library keeps the open spans on a stack of 32 levels. A span gets a self time when its `begin()` and `end()` run in nested order.
- A span with no `end()` call loses its stack level when a span around it ends, or when the stack is full. A span at level 33 clears the stack. The spans below it keep their durations and get no self time.
- `async: true` is for a probe with a span that an `await` splits. Its spans are not on the stack. They give the total time only. They take no time from the self time of another span. Without the option, the spans of other tasks count as spans inside the open span.
- `profiler.time(name, fn)` calls `fn` and times the call with the probe of the name. An error of `fn` goes to the caller. For a result with a `then` function, the span ends when the result settles. `time()` then returns the result of that `then` call, not the result of `fn`.
- `endAfterPaint(token)` ends the span in the first task after the next paint. The duration then includes the style, the layout and the paint of the browser. In a hidden page, or in a context with no `requestAnimationFrame`, it ends the span at once. A page that becomes hidden ends each span that waits. The span has no self time. `endAfterPaint()` and a `wrap()` call with a promise make a small number of objects.
- `slowMs` adds a breadcrumb for each span that is longer than the value. The breadcrumb has the category `profile` and a message such as `grid.render 48 ms`. The next error record carries it. Use a threshold that only a slow span passes, because each breadcrumb is an object.
- `profiler.framePhases: true` adds the phases of each long animation frame to each probe with a span of 1 ms or more in that frame. The library sends them as the histogram `ui.profile.frame.duration` with the attributes `profile.probe` and `profile.frame_phase`. The phases are `script`, `render`, `style_layout` and `forced_layout`. `forced_layout` is the layout time that a script forced with a read after a write. It is a part of the `script` phase.
- `framePhases` uses the last 256 spans of the probes that are not async. `captureLimits.longFramesPerWindow` limits the frames in each window. A browser with no long animation frames reports `capture.install_failed` one time. `framePhases` is then off. Firefox and Safari are such browsers.
- `profiler.framePacing: true` measures the time between two frames with the probe `frame.interval`. The probe uses one of the `maxProbes` slots. The library runs one frame callback for each frame while the page is visible. The first frame after a hidden time gives no value.
- `framePhases` and `framePacing` load as a separate chunk. They need `profiler.enabled`.
- `profiler.maxProbes` is the maximum number of probes. The default is 64. The range is 1 to 1024. You cannot change it after startup. A probe above the limit does nothing. The library reports `config.invalid` one time for each start of the profiler. The diagnostics throttle can drop that report. The library then reports again each time it collects the profiler points, until one report passes the throttle. Each try adds 1 to the `config.invalid` counter.
- Each probe slot holds 2 times 368 bucket counts of 4 bytes, 4 numbers of 8 bytes and 2 numbers of 4 bytes. One slot is 2984 bytes. The library allocates one slot more than `maxProbes` when the profiler first turns on. The default of 64 probes uses 65 slots. That is 193,960 bytes.
- At the end of the first interval with data, the library measures the cost of one `begin()` and `end()` pair. The measurement runs one time. It blocks the thread for approximately 2 ms to 3 ms. Each record from that time has the result as `profile.overhead_ns`. The result is the cost of a pair in a short loop. A pair in app code can cost more or less. `flush()`, `shutdown()` and the exit flush do not run the measurement. A clock that is too coarse gives no value. The measurement can then block for longer.
- With `metricsEndpoint`, a record is an OTLP histogram point. Its point attributes are `profile.probe` and `profile.sample_every` only. The percentiles and the overhead value are on the log record and the ECS document only. A backend computes percentiles from the buckets.
- `processors` and `redact` apply to the `profile.*` attributes of the record. Use a small number of fixed probe names, because each name is one series.
- A rotation sends the open interval as records of the old context. With `securityContext.isolation` (the default), the values of the rotation add no value. Each span that is open at its end also adds no value. On a coarse clock, this includes a span that begins in the last clock tick of the rotation.
- A span that is open when `configure()` turns the profiler off adds no value. During a rotation, `shutdown()` and the exit flush do not send the open interval.
- A name that is not a string, or an empty name, gives a probe that does nothing. A `sampleEvery` value that is not an integer from 1 to 2147483647 uses 1. A `slowMs` value that is not a finite number of 0 or more adds no breadcrumb. An `async` value that is not a boolean uses `false`. Each of these reports `config.invalid` to the current runtime. A call before the first `configure()` reports nothing.
- A probe name stays for the life of the page. The library keeps at most 1024 names. The order of the `probe()` calls decides which probes are in the `maxProbes` limit.
- The clock of the platform limits the resolution of one span. A browser rounds `performance.now()`, for example to 0.1 ms or to 1 ms. A span shorter than one clock step reads 0 or one step.
- Give `end()` only the token of `begin()`. `end(-1)` does nothing. Another token that is not a number, is below 0 or gives a negative duration adds no value. While the profiler is on, the library counts that token as `record.dropped_malformed`.

### Session replay

The session replay records the DOM of the page with the recorder of your app, [`@rrweb/record`](https://rrweb.com/docs/guide). The library keeps the recent events in memory. After an ERROR or FATAL record, it sends them in segments to a separate endpoint. A person can then watch what the user saw before the error.

```ts
configure({
  replay: {
    enabled: true,
    endpoint: "https://replay.example/v1/replay",
    // Your app owns the import. The library has no recorder of its own.
    loader: () => import("@rrweb/record"),
  },
});
```

- The replay is off by default. `@rrweb/record` is an optional peer. An app with the replay off does not need it.
- The buffer keeps the last `replay.bufferMs` (60 seconds by default), and at most 1.5 times that. The recorder takes a full snapshot at each half of that time. `replay.maxBufferBytes` limits the buffer. Above it, the buffer drops its oldest part and reports `capture.rate_limited` at the next upload.
- An ERROR or FATAL record starts an upload. The library sends the buffer, then each new event for `replay.afterErrorMs`. An error in that time is a part of the same upload and does not extend the time. `replay.uploadsPerWindow` limits the uploads in each window of `replay.uploadWindowMs`. A stream of errors then cannot upload the full session. An upload always starts with a full snapshot. For an empty buffer, the library takes a new one.
- The library sends the events in segments. A segment closes at `replay.maxSegmentEvents` events, at `replay.maxSegmentBytes` or after `replay.flushIntervalMs`. One event that is larger than `maxSegmentBytes` is a segment of its own. A full snapshot of a large page is such an event.
- One segment is in flight at a time. A failed send has `replay.maxAttempts` attempts, with the wait of `delivery.retryBaseDelayMs` and `delivery.retryMaxDelayMs`. `delivery.requestTimeoutMs` limits each request. The segments that wait have the limit `replay.maxQueueBytes`. A segment is only in memory. The exit flush sends no segment.
- The request has the headers of `replay.headers`, an object or a function. It does not have the `headers` of the log endpoint, because that token can be for another host. `credentials` applies to the replay request also.
- `replay.maxBufferBytes`, `replay.maxSegmentBytes` and `replay.maxQueueBytes` count the length of the JSON text. A text with a character above U+00FF uses 2 bytes of memory for each character.
- Each segment has `replay.id`, `session.id`, `tab.id`, `service.name` and a `sequence` number. Each record has the attribute `replay.id` while the recorder runs. Use it to find the replay of a log record.
- `replay.onSegment` gets each segment in place of the request. Use it for your own transport. A call that does not end in `delivery.requestTimeoutMs` drops the segment. If the function sends a request, add its URL to `capture.ignoreUrls`. Without that, a failed request gives an error record, and that record gives a new upload.
- **Privacy.** The recorder masks the text of each element. It masks the value of each `input`, `textarea` and `select`, also of a hidden input and a file input. A masked value is `********`. A masked text keeps the length of each word. The text in an element with the attribute `data-observability-unmask` stays. `replay.maskSelectors` is a list of CSS selectors with text that is always masked. `replay.blockSelectors` is a list of CSS selectors of elements that the recorder does not record. The recorder also always blocks each element in `[data-observability-ignore]`, which click capture skips. You cannot turn this off. A password input is always masked. `redact` and `processors` do not apply to a replay event.
- **What stays in clear text.** The recorder does not mask an attribute value, for example `title`, `alt`, `placeholder`, `aria-label`, `data-*`, `id` and `class`. It does not mask the `value` of a checkbox, a radio button, a button and an `<option>`. It does not mask a URL in `href` or `src` with its query, the CSS text, the content of a `<meta>` element and a comment. It records the mouse positions and the scroll positions. The library removes the query of the page URL unless `capture.fullUrls` is set. Block an element with `replay.blockSelectors` when one of these can identify a person or an account.
- Do not put `data-observability-unmask` on an element that shows content from a user. That content can then add text that stays in clear text. With `replay.maskText: false`, a `maskSelectors` entry does not reach an element inside a shadow root.
- A `maskSelectors` or `blockSelectors` entry that is not valid CSS reports `config.invalid`. The replay then does not start, because a missing mask shows text that you wanted to hide.
- With `replay.requireConsent: true`, nothing records before `startReplay()`.
- `stopReplay()` stops the recorder, stops the request in flight and drops each event that is not sent. The recorder then stays off until the next `startReplay()`, also after a later `configure()`. This rule applies with and without `requireConsent`.
- `newSession()` and `rotateSecurityContext()` drop the buffer and start a new recording with a new `replay.id`. The next user of a shared device does not get the page of the previous user.
- A change of another capture setting in `configure()` keeps the recording and its buffer. A change of `replay.endpoint`, a mask setting, a selector list, `recordCanvas`, `bufferMs`, `requireConsent`, `capture.fullUrls` or `capture.ignoreUrls` starts a new recording with a new `replay.id` and drops the buffer. The segment settings, the limits and `replay.headers` apply to the recording that runs. See [Runtime policies](docs/runtime-policies.md).
- `replay.recordOptions` gives other options to the recorder. The library accepts `sampling`, `slimDOMOptions`, `ignoreClass`, `ignoreSelector`, `ignoreCSSAttributes`, `userTriggeredOnInput`, `recordAfter`, `inlineStylesheet` and `dataURLOptions`. It sets each mask, block, canvas, plugin and event option itself. It ignores another key and reports `config.invalid`.
- The recorder reads each DOM change. A change of many nodes costs time and memory. Block a large list with `replay.blockSelectors` when its content is not necessary in the replay.

`replay.plugins` is a list of functions that make the record plugins of the recorder. Your app owns each import.

```ts
configure({
  replay: {
    plugins: [
      async () =>
        (await import("@rrweb/rrweb-plugin-sequential-id-record")).getRecordSequentialIdPlugin(),
      async () =>
        (await import("@rrweb/rrweb-plugin-console-record")).getRecordConsolePlugin({
          level: ["warn", "error"],
        }),
      async ({ transformRequest }) =>
        (await import("@rrweb/rrweb-plugin-network-record")).getRecordNetworkPlugin({
          recordHeaders: false,
          recordBody: false,
          transformRequestFn: transformRequest,
        }),
    ],
  },
});
```

- The sequential id plugin numbers each event. A server can then find a lost event.
- The console plugin and the network plugin wrap the same functions as the console capture and the network capture of the library. Both pairs work together. A plugin event does not pass through `redact`. Do not record headers or bodies unless you mask them in the options of the plugin.
- Give `transformRequest` to the network plugin. It skips each request to a URL in `capture.ignoreUrls`. That list has each endpoint of the library, also `replay.endpoint`. Without it, an upload gives a new event, and that event gives a new upload. It also removes the query of a URL unless `capture.fullUrls` is set.
- The network plugin gives its event some time after the request. An upload directly after a request does not have that event.
- A new `loader` function, `onSegment` function, `recordOptions` object or plugin function in `configure()` starts a new recording and drops the buffer. The library compares the references. Keep them stable, and do not make a new function or object in each `configure()` call.

### Delivery health

`getHealth().delivery` has numbers and times only. It has no response text, no header and no URL.

| Field                 | Description                                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pending`             | The records in the buffers of the library, not yet in a request. A forwarder counts only its own buffers.                                        |
| `inFlight`            | The records in requests that are not complete.                                                                                                   |
| `stored`              | The batches in storage that wait for a retry. A forwarder stores nothing and reports 0.                                                          |
| `lastSendAt`          | The epoch time in ms of the last batch that the server accepted, or null.                                                                        |
| `lastFailureAt`       | The epoch time in ms of the last failed send, or null.                                                                                           |
| `consecutiveFailures` | The failed sends after the last batch that the server accepted. A batch that makes no request does not change it. The exit flush does not count. |
| `throttledUntil`      | The epoch time in ms when the latest server throttle ends, over all endpoints. Null when no endpoint is throttled.                               |
| `dropped`             | The lost records for each `onDrop` reason, from the start of the runtime. A reason with no loss has no key.                                      |

- The library counts `dropped` also without an `onDrop` hook.
- A security context rotation resets `lastFailureAt`, `consecutiveFailures` and `throttledUntil`. It keeps `lastSendAt` and `dropped`.
- `getHealth()` does not wait for startup or for the delivery stack to load.
- The next `configure()` after `shutdown()` starts a new runtime. Each field then starts at zero or null.

### Flush result

`flush(options?)` sends the records in memory and returns a `FlushResult`. Each count is a number of records, not batches.

```ts
const result = await flush({ timeoutMs: 2000 });
if (result.status !== "complete") {
  // Some records have no final state yet. The library still sends or stores them later.
}
```

| Field       | Description                                                                                                                                                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`    | `"complete"`, `"timeout"` or `"inactive"`.                                                                                                                                                                                                              |
| `accepted`  | The records that the transport accepted. For HTTP, the server answered `2xx`. For a custom transport, it returned a `2xx` status. For the transport worker, the worker confirmed the send.                                                              |
| `stored`    | The records that storage keeps after a failed send or a throttle. The retry engine sends them later.                                                                                                                                                    |
| `dropped`   | The records that the library lost. `onDrop` reports them. A record with no destination only counts `record.dropped_no_destination`. A forwarder with no owner drops its records with no `onDrop` report. It reports `bus.no_owner` one time at startup. |
| `forwarded` | In a forwarder, the records that the call gave to the sender. In a sender, 0.                                                                                                                                                                           |
| `pending`   | The records that have no final state at the end of the wait. A store with an unknown result counts here.                                                                                                                                                |

- `timeoutMs` is from 0 to 600000 ms. The default is 5000 ms. The wait includes startup and the load of the delivery stack.
- A `timeoutMs` that is not a number in the range reports `config.invalid`. Options that are not an object also report it. The call then uses 5000 ms. `null` gives 5000 ms with no report.
- The snapshot is the records in memory at the call. These are the records in the buffers, the queued batches and the batches in flight. A record that you log after the call is not in the snapshot.
- Before startup ends, the call waits for startup first. The snapshot then also has the records that you log during that wait.
- Two calls at the same time each have a snapshot and a time limit. A batch that is in flight at both calls counts in both results.
- `status` is `"complete"` when `pending` is 0.
- `status` is `"timeout"` when `pending` is more than 0. The time limit passed, or a store passed its own time limit. A pause, a `shutdown()` or a rotation that ends the wait also gives `"timeout"`.
- During a rotation, the records of the old context wait for the `pending` rule of the rotation. The result counts them as `pending`.
- At the time limit, the call returns. The library does not cancel the work. A batch that ends later goes to the server or to storage as usual. The result does not change.
- `status` is `"inactive"` before the first `configure()` call that works, after a failed first call, while `enabled` is false and after `shutdown()`. The call sends nothing and waits for nothing. `pending` is the count of the records that wait in memory. The other counts are 0.
- A forwarder gives its records to its sender and asks the sender to flush. The sender gets 90 percent of the time that is left. The rest is for the answer. `status`, `accepted`, `stored`, `dropped` and `pending` come from the answer of the sender. They count all records in the snapshot of the sender. That includes the records of other contexts.
- A forwarder that gets no valid answer in time counts its forwarded records as `pending`. A sender on an older version does not answer.
- A forwarder with no owner sends nothing. It counts its records as `dropped` and returns `"complete"` at once.
- A flush that a frame or a worker asks for does not send the open interval of the metrics and the profiler of its sender.
- The batches in storage from earlier failures are not in the snapshot. `getHealth().delivery.stored` counts them. The call starts no drain.
- Replay segments and the exit flush are not in the snapshot.

### Shutdown options

`shutdown(options?)` takes `pending` and `clearStorage`.

```ts
// Logout on a shared device: send nothing more, and remove the stored data.
await shutdown({ pending: "discard", clearStorage: "context" });
```

| Option         | Values                                          | Effect                                                                                                                                                                                |
| -------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pending`      | `"flush"` (default), `"discard"`                | `"flush"` sends the records in memory, then runs the exit flush. `"discard"` sends nothing and runs no exit flush.                                                                    |
| `clearStorage` | `"context"`, `"namespace"`. Not set by default. | Removes the stored batches, the emergency queue entries, the stored session id, the tab id and the journey. `"namespace"` removes the batches of each context in `storage.namespace`. |

- A discard reports each record in memory to `onDrop` with the reason `"discarded"`. A request in flight can still reach the server. The library does not report its records. Its result writes nothing and starts no retry.
- A discard stops the captures, the replay recorder, the retry engine and the pipeline. The replay recorder drops its buffer and its upload queue.
- A discard also clears the breadcrumbs, the ambient context, the debug buffer and the active journey of the stopped runtime. The stored journey stays, unless `clearStorage` removes it.
- `clearStorage` always discards. With `pending: "flush"`, the library reports `config.invalid` and discards.
- `"context"` also removes the batches that a carry during a pause left under an older context.
- `clearStorage: null` removes nothing, as when it is not set.
- An invalid `pending` value reports `config.invalid` and discards. An invalid `clearStorage` value reports `config.invalid`, discards and removes the `"context"` scope.
- A value that is not an object, for example `shutdown("discard")`, reports `config.invalid` and discards.
- A later `shutdown()` stops nothing more. Its `clearStorage` still removes the stored data of the stopped runtime. The removal waits until the first `shutdown()` ends, so a late save of the first flush cannot land after it.
- After `shutdown()`, `startJourney()` and `adoptJourney()` keep the journey in memory only. They write nothing to `sessionStorage`.
- Before the first `configure()` call that works, no store is known. `clearStorage` then removes nothing. After a first `configure()` with `enabled: false`, it opens the configured store to remove the data.
- Late work after a discard writes nothing. This applies to a request result, a delivery stack load, the rotation code, a capture import and a replay upload.
- A rotation that already stops the old sender ends first. Its own rule applies to the records of the old context. A rotation that did not reach that step stops and rejects.
- A rotation that the shutdown stops after it took the old records rejects. `onDrop` reports the records that it took and that nothing keeps, with `security_context`. A rotation that the shutdown meets in its storage step does not apply the new context.

## Configuration Options

Set `endpoint` and `serviceName` in the first `configure()`. Without them, the library reports `config.invalid`. Set `endpoint: null` for console-only mode. A value of the wrong type or outside its range reports `config.invalid`. The current value stays. Level names can have any case. You cannot change `batching` and `retention` after the delivery stack loads. The first `configure()` call that works sets `limits`, `journey.maxAgeMs`, `profiler.maxProbes`, `correlation`, `identity`, `storage`, `bus.mode` and `bus.openFinRole`. This is also true after an early log call. A later change of these settings reports `config.invalid`. A key that the library does not know reports `config.invalid`, for example `The library ignores the unknown config key "delivery.batchesPerDrain". Check the spelling.` [Runtime policies](docs/runtime-policies.md) gives each default and range of the policy sections.

Each `configure()` call merges its keys into the current settings. These rules apply to each key at each depth.

- An omitted key keeps its current value. A key with the value `undefined` also keeps its current value. Thus an unset environment variable cannot remove `redact`.
- `null` removes a hook, for example `redact`, `onDrop` or `transport`. `null` also removes the `headers`.
- A `redact` value that is not a function keeps the current hook. Without a current hook, the library drops each record until `redact` is a function or `null`.
- `null` turns off an endpoint. This applies to `endpoint`, `metricsEndpoint`, `tracesEndpoint` and `replay.endpoint`. On the last three keys, an empty or blank string also turns the endpoint off and reports `config.invalid`. On `endpoint`, an empty string is the same as a missing endpoint. A blank `endpoint` reports `config.invalid`, and the current value stays.
- A relative endpoint URL resolves against `document.baseURI`, or against `location.href` without a document. The library keeps the absolute URL and reports the origin that receives the records. An endpoint URL with a user name or a password reports `config.invalid`, and the current value stays.
- A `processors` list with an entry that is not a function keeps the current list. Without a current list, the library drops each record until `processors` is a list of functions or `[]`.
- If the first `configure()` call cannot read its options, for example because a getter throws, the library writes a warning to the console. It installs no capture and drops each record until a `configure()` call sets `redact` to a function or to `null`. A call that leaves out `redact` does not end this state, because the library cannot know which `redact` the app meant. A later call that fails keeps the current settings. `configure()` never throws.
- On a limit key, `null` sets no limit. `0` sets a limit of zero, so the library allows nothing. Some limit keys do not accept `0`, because zero stops the feature.
- `null` on a key that does not accept `null` reports `config.invalid`. The current value stays.
- Some settings need another setting. For example, `transportOnExit` needs `transport`. A call that sets one of them without the other reports `config.invalid`. The values stay.

| ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`                                                                    | Unset                                                                                                                                                                                                                                     | HTTP endpoint that receives the batches. `null` selects console-only mode. A missing endpoint or `""` reports `config.invalid`. A relative URL resolves against the page. ### Deferred payloads

```ts
configure({ payloadMode: "defer" });
const payload = { status: "before" };
getLogger("orders").info("Order state", payload);
payload.status = "after";
```

With `defer`, the record sees `status: "after"` if the idle build runs after the assignment. With the default `copy`, it sees `"before"`. The queue keeps the payload reference without reading its fields. Error reasons and metric attributes also wait for the build. Console output and breadcrumbs wait with the record. A call below the level queues nothing unless the console uses it. Sampling checks use the current rules at build time.

The call keeps its timestamp, trace, journey and a shallow copy of the ambient context. The builder reads `contextProvider`, scoped context and payload fields at build time. Processors and `redact` also run at build time. The queue can hold raw values until then. Debug bundle output does not include those raw queued values.

`requestIdleCallback` builds records while idle time remains. A callback timeout of 1000 ms permits one build without idle time. A timer runs the build when the idle API is absent. `flush()`, shutdown and page exit build pending records first. Reconfiguration, session changes and delivery identity changes also drain pending calls first.

The queue holds at most 1000 calls for each runtime. A lower positive `buffering.maxPendingRecords` also lowers this cap. A full queue builds its calls before it accepts another payload reference. Calls from a hook wait for the next callback. Extra calls from a hook at the cap increment `record.dropped_by_ceiling`. The library does not build those calls.

The deferred cap is separate from the delivery buffer. Delivery byte budgets and stats apply to built records. With `debugBuffer.enabled`, the logger builds every record at the call, also with `payloadMode: "defer"`. This preserves the debug buffer's immediate privacy processing.

### Remote capture switches

```ts
configure({
  sampling: { remote: true },
  capture: { remoteToggles: ["fetch", "resourceTiming", "lifecycle"] },
});
```

```http
X-UiObs-Sampling: {"v":1,"ttlMs":60000,"capture":{"fetch":true,"lifecycle":false}}
```

The rules change only the switches in this context's `remoteToggles`. The empty default list permits no changes. Each switch is boolean. An invalid switch or a privacy control rejects the whole header. The allowed names are `errors`, `rejections`, `resourceErrors`, `fetch`, `xhr`, `httpMetrics`, `interactions`, `navigation`, `webVitals`, `longFrames`, `console`, `webSocket`, `uncleanExit`, `userTiming`, `serverTiming`, `reports`, `resourceTiming` and `lifecycle`.

A remote enable keeps the local options object of a capture, for example click privacy settings or console levels. A capture that is `false` locally gets its defaults. For `webVitals`, the defaults have no loader, so only the navigation timing runs. The server cannot change text capture, selectors, URL rules, trace propagation, plugins or thresholds. The library restores local settings when the TTL ends, remote sampling stops, or the delivery identity changes. The trusted sampling path also sends these rules to forwarders. Each forwarder applies its own allowlist.

### Auto-Capture Options

```ts
capture: {
  errors: true,          // Uncaught window.onerror exceptions (default: true)
  rejections: true,      // Unhandled promise rejections (default: true)
  resourceErrors: false, // <img>, <script>, <link> load failures
  fetch: false,          // window.fetch duration and status codes
  xhr: false,            // XMLHttpRequest duration and status codes
  httpMetrics: true,     // http.client.request.duration histogram of fetch and xhr requests, in seconds.
                         // Attributes: http.request.method, http.response.status_code, server.address, error.type
  interactions: false,   // Click action names. The object form sets actionAttribute, text, selector,
                         // rageClicks and deadClicks
  navigation: false,     // Single-page navigation URL changes
  webVitals: false,      // Core Web Vitals (LCP, CLS, INP, FCP, TTFB). Object: { loader }
  longFrames: false,     // Frames that freeze the page, as ui.long_frame.duration.
                         // Object: { thresholdMs }, with default 100
  console: false,        // App console calls. true wraps error and warn.
                         // Object: { levels }, for example { levels: ["error", "warn", "info"] }
  fullUrls: false,       // Keep query strings and fragments on recorded URLs
  urlTransform: undefined, // Function that replaces the default URL rule
  ignoreUrls: [],        // URL patterns excluded from network capture
  propagateTraceHeaderTo: [], // Origins, or RegExp patterns, that receive traceparent
  webSocket: false,      // WebSocket open, close and error, and ui.websocket.messages
  uncleanExit: false,    // WARN ui.unclean_exit when the previous page of the tab did not close cleanly
  userTiming: false,     // performance.measure() as ui.user_timing.duration. A mark gives a breadcrumb.
                         // Object: { include }. The default [] records each name
  remoteToggles: [],     // Capture switches that a remote rule can change for its TTL
  serverTiming: false,   // Server-Timing entries on fetch and XHR records
  reports: false,        // Browser reports as WARN ui.report
  resourceTiming: false, // Resource durations. An object sets slowMs, with default 1000
  lifecycle: false,      // Page states and the duration of the previous state
  plugins: [],           // Capture plugins of your app
}
```

`interactions`, `webVitals`, `longFrames`, `console`, `userTiming` and `resourceTiming` take `true`, `false` or an options object.

- `true` turns the capture on with the default options.
- An object turns the capture on. An omitted field keeps its current value. After `true` or `false`, an omitted field takes its default.
- `httpMetrics` and `serverTiming` are booleans only, because they apply to the fetch capture and the xhr capture.
- The URL rules `fullUrls`, `ignoreUrls`, `propagateTraceHeaderTo` and `urlTransform` are keys of `capture` too. They are not capture switches.

`interactions: { rageClicks: true, deadClicks: true }` finds frustrated clicks. Each event names only the action, in `click.action`.

- A rage click is `rageClickCount` clicks (default 3) on one element in `rageClickWindowMs` (default 1000). It gives the event `ui.rage_click` with `click.count`. More clicks in the same burst give no second event. A burst ends when no click stays in the window.
- A dead click is a click on a control that gives no DOM change, no navigation and no scroll in `deadClickMs` (default 1000). It gives the event `ui.dead_click`. A control is a button, a link, a `role="button"` element or an element with the action attribute. A click on a `target="_blank"` or `download` link gives no event.
- A request alone is not a response. A page that changes its DOM all the time gives no dead click.

`uncleanExit` finds a page of this tab that stopped without a clean close, for example after a crash. The top document keeps a marker in `sessionStorage`. A clean close removes it. The next page of the tab logs WARN `ui.unclean_exit`. A popup with an opener reports nothing, because it copies the `sessionStorage` of its opener. A duplicated tab copies it too, and can report a false exit. `identity: "memory"` turns this capture off, because that mode writes nothing to the device.

- The attributes are `exit.session_id`, `exit.last_seen_ms`, `exit.visibility` and `exit.discarded`.
- The marker updates every 30 seconds and at each visibility change. `exit.last_seen_ms` is correct to about 30 seconds.
- A mobile OS can stop a hidden page with no close event. `exit.visibility: "hidden"` shows this case. `exit.discarded: true` shows a page that the browser discarded to free memory.

`userTiming` records each `performance.measure()` of the app in the histogram `ui.user_timing.duration`, in milliseconds, with the attribute `user_timing.name`. Each `performance.mark()` adds a breadcrumb. Frameworks create many marks and measures. Set `userTiming: { include: [/^app\./] }` to keep only the names of your app. `metrics.maxSeries` limits the number of names in one interval. Names follow `fullUrls`. Without it, a name loses the part after the first `?` or `#`.

`serverTiming` reads the `Server-Timing` response header of captured fetch and XHR requests. It adds `server.timing` entries with `name`, `duration` and `description`. A valid `traceparent;desc="00-<trace-id>-<span-id>-01"` adds an OTLP link to the client span. The client span keeps its own trace and parent. Set `tracesEndpoint`, `propagateTraceHeaderTo`, and `capture.fetch` or `capture.xhr` to record client spans.

For cross-origin requests, expose `Server-Timing` with `Access-Control-Expose-Headers`. Also send `Timing-Allow-Origin` for access through browser performance tools. The [Server Timing specification](https://www.w3.org/TR/server-timing/) defines that interface. The library reads at most 4096 header characters and 32 entries. The privacy hooks process the entries before delivery.

`reports` records deprecations and interventions through ReportingObserver. CSP reports use the `securitypolicyviolation` event. Each WARN `ui.report` has the type, the URL and the available source location or CSP directive. Report URLs never keep credentials, queries or fragments. This rule also applies with `fullUrls` or `urlTransform`. Message text and code samples stay out.

`resourceTiming: true` records the histogram `ui.resource.duration` in milliseconds. Its attributes are `resource.initiator_type` and `server.address`. Each resource at or above 1000 ms also gives `ui.resource.slow`. Set `resourceTiming: { slowMs: 500 }` to change the threshold. Set `slowMs: 0` for no slow events. The capture skips ingest endpoints, ignored URLs and non-HTTP resources. Only the first install reads buffered resources. `metrics.maxSeries` limits the host and initiator series.

`lifecycle` records `ui.lifecycle` at install and on each state change. The states are `visible`, `hidden`, `frozen`, `resumed` and `restored`. `restored` means a back-forward cache restore. Each event has `lifecycle.previous_state` and `lifecycle.duration_ms`. A monotonic clock measures the duration.

The three captures have separate rate limits in `captureLimits`. They use `captureLimits.windowMs`, which defaults to 10000 ms. Disabling a capture removes its listeners or disconnects its observer.

`longFrames` records each frame at or above `longFrames.thresholdMs` (default 100) as the histogram `ui.long_frame.duration`. Set `longFrames: { thresholdMs: 200 }` to record only longer frames. Each long frame also adds a breadcrumb. The next error record then shows the freeze before it.

- The library observes `long-animation-frame`. A browser without it gives `longtask` entries, with no script attributes.
- The attributes are `frame.type`, `frame.blocking_ms`, `frame.script.invoker` and `frame.script.source`. The source URL follows `fullUrls`.
- The library records at most 20 long frames in each 10-second window.

`capture.console` records the console calls of your app and of third-party code. It is different from the top-level `consoleOutput` option, which prints records.

> **Set `redact` before you turn on `capture.console`.** A call such as `console.error("Request failed", error.response)` sends the request headers, for example `Authorization`. Third-party code on the page writes such lines too.

- `true` wraps `console.error` and `console.warn`. `{ levels }` selects from `error`, `warn`, `info` and `log`. An empty `levels` list wraps nothing.
- `error` gives an ERROR record, and `warn` gives a WARN record. `info` and `log` give a breadcrumb only.
- The first string is the message. The first `Error` of an `error` call gives the `error.*` fields. The other arguments go into `console.args`.
- The wrapper calls the original method first. Devtools shows the same text. The source link of the line points to the library wrapper.
- The library does not record the lines that it prints itself.
- The library records at most 20 `error` and `warn` calls in each 10-second window. The error capture has a separate limit. Console noise cannot hide an uncaught error.
- To record an argument, the library reads each property, also a getter. A getter with a side effect then runs during the console call.
- On `shutdown()`, the library restores each method. If another script wrapped the method later, the library leaves it and reports `capture.install_failed`.

`webSocket` records the lifecycle of each WebSocket that the app opens after the capture loads.

- `websocket.open` and `websocket.close` are events. `websocket.error` is a WARN record. Each has `url.full` and `server.address`.
- `websocket.close` adds `websocket.close.code` and `websocket.close.clean`.
- `url.full` has no user info, no query and no fragment, also with `fullUrls`. A socket URL often holds a token. Only `urlTransform` can record more of the URL.
- The counter `ui.websocket.messages` counts the messages, with `network.io.direction` (`transmit` or `receive`) and `server.address`.
- The library never reads the content of a message.
- The library records at most 20 lifecycle records in each 10-second window. The counter counts each message.

`plugins` adds your own capture modules. A plugin is an object with `name`, `install(ctx)` and `uninstall()`.

- `ctx` gives `logger`, `counter()`, `histogram()`, `addBreadcrumb()` and `ownRequest(fn)`. The logger namespace is `uiobs.capture.<name>`.
- `ownRequest(fn)` runs `fn`. The network capture does not record a request that `fn` starts before its first `await`, and does not add `traceparent` to it.
- A `configure()` that changes the capture section calls `uninstall()`, then `install(ctx)` again. `shutdown()` calls `uninstall()`.
- If `install()` or `uninstall()` throws, the library reports `capture.install_failed`. The other capture modules keep working.
- The console-only runtime next to another version of the library installs no plugin.

```ts
import { type CapturePlugin, configure } from "@utk09/ui-observability";

let onChange: (() => void) | undefined;

const visibility: CapturePlugin = {
  name: "visibility",
  install(ctx) {
    onChange = () => {
      ctx.logger.logEvent("page.visibility", { state: document.visibilityState });
    };
    document.addEventListener("visibilitychange", onChange);
  },
  uninstall() {
    if (onChange) {
      document.removeEventListener("visibilitychange", onChange);
    }
  },
};

configure({ endpoint: "https://ingest.example/v1/logs", capture: { plugins: [visibility] } });
```

`fullUrls` is off by default. The library then cuts each recorded URL at the first `?` or `#`. This applies to the page URL, the request target and the URL of a failed resource. `ignoreUrls` and a RegExp in `propagateTraceHeaderTo` match the full URL. `urlTransform` replaces this rule. It receives the original URL. If it throws, the library records an empty URL and reports `capture.record_failed`.

`propagateTraceHeaderTo` needs `capture.fetch` or `capture.xhr`. Without them, the library reports `config.invalid`. A string in `propagateTraceHeaderTo` is an origin, for example `"https://api.example"`. It matches a request to that origin only. A URL with a path gives its origin. A relative request URL resolves against the page. To match a path, use a RegExp. A RegExp tests the request URL in the form that the caller gives. Start each RegExp with `^`. Without it, `/\/api\//` also matches `https://vendor.example/api/`. For example, `/^https:\/\/api\.example\/v2\//` matches one path on one origin. `/^\/api\//` matches a relative request URL only.

### Spans

With `tracesEndpoint`, the library sends spans. The backend then has a root span for each trace of the library.

- **Root span:** Each ambient trace has one root span of kind INTERNAL. It starts with the trace and ends when the trace rotates. Its name tells why the trace started: `ui.start`, `ui.interaction`, `ui.navigation` or `ui.trace`.
- **Client span:** Each `fetch` or XHR request that gets `traceparent` from `capture.propagateTraceHeaderTo` has one span of kind CLIENT. The `traceparent` names the client span, and the root span is its parent. Its name is the HTTP method. Its attributes are `http.request.method`, `url.full`, `server.address`, `http.response.status_code` and `error.type`. A status of 0 or 400 and more sets the status ERROR. A `fetch` request that already has a `traceparent` header keeps it. The library then records no client span and reports `capture.trace_header_kept`.
- **Measure span:** Each `startMeasure()` call has one span of kind INTERNAL under the root span. Each phase has one child span. Sampling and the OpenTelemetry rule apply to it as to a client span.
- **Sampling:** `sampling.defaultRate` samples each trace by its trace id. The whole trace stays or goes. `minLevel` does not apply to a span. For a trace that sampling drops, the `traceparent` has the sampled flag off. A downstream service then drops its spans too.
- **Exit:** The exit flush and `shutdown()` end the root span of the active trace. The root span of a trace ends one time. A tab that becomes hidden ends it too, because a mobile OS can stop a hidden page.
- **OpenTelemetry:** With `otelLoader`, a trace from the OpenTelemetry API keeps its own spans. The library sends no span for it.
- `getTraceHeaders()` names the root span. Your server span is then a child of the root span.
- Span records go through `processors` and `redact`. They also carry the context attributes of a record, for example `page.url` and `journey.id`.

## Core Architecture

- **Code splitting:** The main chunk holds the logger, the record builder and the console sink. The delivery stack loads only when you set an endpoint. The bus loads only when the context needs it. Each capture module loads only when you enable it. The rotation code loads on the first `rotateSecurityContext()` call.
- **Document singleton:** The library keeps the runtime at `globalThis[Symbol.for("ui-observability.runtime")]`. Federated microfrontends and separate bundles share one buffer, one sequence and one transport.
- **One sender:** Iframes, workers and OpenFin views find the nearest long-lived context. They forward their records to it over the bus. That context batches, stores and sends for all of them. By default, a parent accepts only the frames and workers that it registers with `registerFrame()` and `registerWorker()`. A frame that knows its owner relays the records of its own children.
- **One sender for each tab:** Each top-level tab or window has its own sender. Two tabs of one origin send their records separately. They have the same `session.id` and a different `tab.id`. A retry of stored batches runs in one tab at a time, under a Web Lock for each storage namespace.
- **Five correlation ids:** Each record carries `session.id`, `tab.id`, `context.id`, `journey.id` and `trace_id`.
- **Durability and exit flush:** The library stores a batch that fails to send, in IndexedDB or localStorage. It sends the batch again with exponential backoff and jitter. When the document becomes hidden, the library runs a normal flush with the headers, gzip and retry. While the document is hidden, a send of 60 KB or less uses `keepalive`. A mobile OS can stop a hidden page with no `pagehide`. On `pagehide`, `freeze` or OpenFin close, it sends pending records in the exit flush if they are below 60 KB. To an endpoint on another origin, the exit flush sends a `text/plain` keepalive fetch that obeys `credentials`. With `credentials: "include"`, it uses `navigator.sendBeacon` for that batch, because a beacon always sends the cookies. With `headers`, it uses a keepalive fetch with the last headers, because a beacon cannot set a header. An endpoint on the origin of the page also gets a keepalive fetch, with the content type of the serializer. A larger payload goes to the emergency queue. `shutdown()` runs a normal flush before the exit flush. It then cancels a request that is still open. A stored batch of that request stays in storage. An action is an audit fact. When storage is over `retention.maxBatches` or over the quota of the browser, it removes the batches without an action first. Before startup, each hold buffer keeps up to 2000 actions. `buffering.maxHeldRecords` limits the other records. Its default is 500. A full hold buffer keeps its first 100 records of each kind. `onDrop` tells the app about each loss.
- **Server (Node):** On Node, for example during server-side rendering, the library runs console-only. It installs no capture, keeps the ids in memory, uses no storage and has no exit flush. If you set `endpoint`, `metricsEndpoint`, `tracesEndpoint` or `transport`, it reports `config.invalid` one time.
- **One library version on a page:** If a copy of another version owns the page runtime, this copy runs console-only. It installs no capture and reports `runtime.version_mismatch`. Load one version of the library on the page.
- **Emergency queue:** The emergency queue is best effort. With `storage.backend` `"memory"` or `"none"`, the exit flush does not use it. A batch that it cannot send is then lost, and `onDrop` reports `not_stored`. It writes to `localStorage` synchronously, because no other storage works while the page unloads. If the browser refuses the write, the library reports `storage.quota_exceeded`. The library then loses the batch.
- **Configuration after startup:** A second `configure()` call merges accepted options into an unlocked live runtime. Isolation is on by default. Then `configure()` refuses changes to routing settings and to the context ID. It keeps the current values, reports `config.invalid` and applies the other settings. Use `rotateSecurityContext()` for these changes. `securityContext.isolation: false` restores ordinary mutable routing. The runtime also refuses these 8 changes and reports `config.invalid` for each:
  - A change to the `storage` section. The stored batches stay in the adapter that the runtime built at startup.
  - A change to `identity`. The ids exist from startup.
  - A change to `correlation`. The runtime reads it one time, at startup.
  - A change to `bus.mode` or `bus.openFinRole`. The bus reads them one time, when it starts.
  - A change to `batching` or `retention` after the delivery stack loads. The stack reads them one time.
  - A change to `limits` or `journey.maxAgeMs` after the first `configure()`. The record builder and the journey engine read them one time.
  - A change to `profiler.maxProbes` after the first `configure()`. The profiler sets the size of its typed arrays from the startup value.
  - An `endpoint` change to `null` after the delivery stack loads. Without an endpoint, the stored batches would be lost. With isolation off, a change to another endpoint URL is accepted.
- **Deterministic sampling:** FNV-1a hashing applies one keep rate to a whole journey. Sampling always keeps an explicit action and each record at or above `sampling.alwaysSampleFrom`, default `"ERROR"`.

## Ingest Server Requirements

The ingest server must meet these requirements:

1. **Protocol:** Accept `POST` with `Content-Type: application/json` or `text/plain;charset=UTF-8`. Without `headers`, the exit flush sends a `text/plain` batch to an endpoint on another origin. That content type needs no CORS preflight.
   - With `credentials: "omit"` or `"same-origin"`, that batch is a keepalive `fetch` with no custom header. It obeys `credentials`. Thus it sends no cookie to another origin.
   - With `credentials: "include"`, that batch is a beacon. `sendBeacon` always sends the cookies. Thus the library uses it only when the app asks for cookies.
   - The batch id and the exit reason are in the query parameters `uiobs_batch_id` and `uiobs_exit`.
   - The answer to the keepalive `fetch` must permit the origin. If it does not, a page that is still open sends the batch again at the next page load.
   - It is possible that a keepalive `fetch` is less reliable than a beacon at page exit in some browsers. This is a hypothesis. `e2e/exit-flush.e2e.ts` shows that the `fetch` arrives after a navigation in Chromium, Firefox and WebKit.
   - An endpoint on the origin of the page gets the exit batch with the content type of the serializer. For OTLP, that is `application/json`. A same-origin request needs no CORS preflight. A sandboxed frame, a `srcdoc` frame and an `about:blank` frame still send the `text/plain` batch.
   - A stock OpenTelemetry Collector accepts only `application/json` or protobuf. On another origin, it refuses the `text/plain` exit batch with `415`. The library loses that batch.
   - To prevent this loss, set `headers` or put a same-origin proxy in front of the collector.
   - With `headers`, the exit flush sends a keepalive `fetch` with the content type of the serializer, `application/json` for OTLP. To another origin, that request needs a CORS preflight.
   - It is possible that a browser cancels that request during page exit. No test in this repository checks this risk.
2. **Preflight:** Answer `OPTIONS` on the ingest path, and allow the request headers:

   ```http
   Access-Control-Allow-Headers: content-type, content-encoding, x-uiobs-batch-id, x-uiobs-attempt
   ```

   - The transport sends `X-UiObs-Batch-Id` and `X-UiObs-Attempt` with each batch.
   - Above 1 KiB, it also sends `Content-Encoding: gzip`.
   - Each of these headers causes a CORS preflight. If the server does not allow them, each preflight fails.
   - After a failed preflight, the library tries the batch 5 more times. It then drops the batch.
   - Only the `text/plain` batches of the exit flush arrive, because they have no custom header.

3. **Deduplication:** Deduplicate on the `X-UiObs-Batch-Id` header and the `uiobs_batch_id` query parameter. Keep the ids for at least 24 hours.
4. **Throttling:** Return `429` or `503` with `Retry-After`. Expose the header with `Access-Control-Expose-Headers: retry-after`. The library waits 60 s at most.
5. **Status codes:** `200`, `202` and `204` accept the batch. `413` makes the library split the batch. A `413` body can give the limit as JSON, for example `{"maxBytes": 65536}`. The library reads at most 16 KiB of a response body. `delivery.requestTimeoutMs` also limits that read. An OTLP `2xx` answer can have `partialSuccess` in a JSON body. The library gives the rejected count to `onDrop` with the reason `partially_rejected`. It does not send the batch again. With a `headers` function, a `401` or `403` gets one more send with new headers. The library drops a batch that gets any other `4xx`.
6. **Metrics and traces endpoints (optional):** With `metricsEndpoint`, the library sends each batch of metric records there as an OTLP/JSON `ExportMetricsServiceRequest`. With `tracesEndpoint`, it sends each batch of span records there as an OTLP/JSON `ExportTraceServiceRequest`. The rules 1 to 5 also apply to these endpoints. A throttle or a failed batch of one endpoint does not hold back the batches of another endpoint. `headers` applies to each endpoint. Each point is a delta from the previous point of its attribute set. A histogram point with a negative value has no `sum`.
7. **Remote sampling (optional):** To send sampling rules, add `X-UiObs-Sampling` to a `2xx` answer. Expose the header with `Access-Control-Expose-Headers: x-uiobs-sampling`.
8. **Clock offset (optional):** Expose the `Date` header with `Access-Control-Expose-Headers: date`. Each later log and span record then carries `uiobs.clock_offset_ms`.

**Replay endpoint (only with `replay.endpoint`).** It is a separate URL. It gets one `POST` for each segment of the session replay.

- The body is JSON, with `Content-Encoding: gzip` when `compression` is `gzip`. It has `replay.id`, `session.id`, `tab.id`, `service.name`, `sequence`, `bytes` and `events`. `events` is the list of recorder events.
- The request has `X-UiObs-Batch-Id` with the value `<replay.id>-<sequence>`, `X-UiObs-Attempt` and the headers of your `replay.headers` option. Allow them in the preflight, as for the log endpoint. Store a segment one time for each batch id.
- Answer `2xx` for a stored segment. The library sends a segment again after `429`, `5xx`, `401` and `403`. It drops a segment after another `4xx` status.
- Accept a large body. The first segment of an upload has a full snapshot of the page. One snapshot of a page with 35,000 table cells was 4.7 MB of JSON. The library does not split one event.
- Keep the segments of one `replay.id` in the order of `sequence`. A player needs the segment with the full snapshot before the later segments.
- `tools/mock-ingest-server.mjs` and `tools/reference-collector.mjs` accept `/v1/replay` and print one line for each segment. The reference collector accepts a replay body of at most `MAX_REPLAY_BODY_BYTES` (16 MB by default). `uiobs doctor` tests the replay endpoint with the option `--replay`. See [Check an ingest server](#check-an-ingest-server).

`tools/reference-collector.mjs` implements each rule with no dependencies. It is not part of the package. Run `node tools/reference-collector.mjs`. Set `ALLOWED_ORIGINS` to the origins of your app. Set `UPSTREAM_URL` to an OTLP/HTTP collector, for example `http://localhost:4318`, to forward each OTLP batch there. The file lists the other settings: `PORT`, `AUTH_TOKEN`, `SAMPLING_RULES`, `MAX_BODY_BYTES` and `MAX_REQUESTS_PER_SECOND`.

### Check an ingest server

Run the command line tool against your ingest URL. Give the origin of your app.

```bash
pnpm dlx @utk09/ui-observability doctor https://ingest.example/v1/logs --origin https://app.example
```

The tool prints `PASS` or `FAIL` for each rule. The exit code is 0 when each rule passes, 1 when a rule fails and 2 for a wrong command.

| Rule              | Check                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| `preflight`       | `OPTIONS` answers with a `2xx` status and permits the origin.                                    |
| `allowed headers` | The preflight allows each request header of the library.                                         |
| `test batch`      | A `POST` of an OTLP batch gets a `2xx` status and permits the origin.                            |
| `exposed headers` | The batch answer exposes `Retry-After`. The output names optional headers that stay hidden.      |
| `gzip`            | A `POST` with `Content-Encoding: gzip` gets a `2xx` status.                                      |
| `deduplication`   | A second `POST` with the same `X-UiObs-Batch-Id` gets a `2xx` status.                            |
| `beacon`          | A `POST` with `text/plain;charset=UTF-8`, the exit batch to another origin, gets a `2xx` status. |

- The tool sends real test batches. Each record has `service.name: "uiobs-doctor"`. Expect four test batches in the store of the server.
- The `beacon` batch has its batch id in `uiobs_batch_id` and the reason `pagehide` in `uiobs_exit`, as in the exit flush of the library.
- The exit flush sends that batch as a keepalive `fetch`, or as a beacon with `credentials: "include"`. The rule applies to the two.
- A stock OpenTelemetry Collector answers `415` to the `beacon` batch. The `FAIL` line then names the two corrections of requirement 1.
- The exit flush sends no `text/plain` batch to an endpoint on the origin of the page. For such an endpoint, a failed `beacon` rule causes no loss. A sandboxed frame, a `srcdoc` frame and an `about:blank` frame are exceptions, because they send the `text/plain` batch.
- The tool sends no credentials by default. Add a request header with `--header "Name: value"`. You can give the option more than one time.

  ```bash
  pnpm dlx @utk09/ui-observability doctor https://ingest.example/v1/logs --origin https://app.example --header "Authorization: Bearer $TOKEN"
  ```

- The tool sends each custom header with each batch. The preflight names the header, and `allowed headers` tests that the server allows it.
- With a custom header, the tool sends no `beacon` batch. The exit flush of the library then uses a keepalive fetch with the content type of the serializer.

To test a replay endpoint, give the value of `replay.endpoint` and add `--replay` directly after the origin. Give each header of your `replay.headers` option with `--header`.

```bash
pnpm dlx @utk09/ui-observability doctor https://ingest.example/v1/replay --origin https://app.example --replay
```

| Rule              | Check                                                                    |
| ----------------- | ------------------------------------------------------------------------ |
| `preflight`       | `OPTIONS` answers with a `2xx` status and permits the origin.            |
| `allowed headers` | The preflight allows each request header of the library.                 |
| `test segment`    | A `POST` of a small segment gets a `2xx` status and permits the origin.  |
| `gzip`            | A `POST` of a segment with `Content-Encoding: gzip` gets a `2xx` status. |
| `large segment`   | A `POST` of a segment of 5 MB without gzip gets a `2xx` status.          |
| `deduplication`   | A second `POST` with the same `X-UiObs-Batch-Id` gets a `2xx` status.    |

- The tool sends four real test segments with one `replay.id`. Each segment has `service.name: "uiobs-doctor"` and one custom event of the recorder. One segment has 5 MB.
- The `large segment` rule finds a body limit that is too low. The library drops a segment after a `413` status, and the first segment of an upload has a full snapshot of the page.
- The tool sends no beacon to a replay endpoint, because the exit flush sends no segment.
- The tool prints no header value. A header value stays in the history of your shell. Use an environment variable for a token.
- A custom header cannot have the name of a header that the tool sets, for example `Content-Type` or `Origin`.
- A client cannot see the store of the server. `deduplication` proves only that the server accepts a repeated id.
- The tool follows no redirect. A `3xx` answer is a failure, because a browser refuses a preflight that redirects.
- An origin has no path and no trailing slash. A wrong command prints the usage and the arguments that the tool received.
- The tool needs Node 22.22.3 or later.

## Development

Use Node 22.22.3 or later and pnpm 12.21.0. `.nvmrc` selects the minimum Node version.
The `packageManager` field pins pnpm. See the [pnpm installation instructions](https://pnpm.io/installation).
Angular supports Node `^22.22.3 || ^24.15.0 || >=26.0.0`.
Use one of these Node versions for the complete workspace.

Install from the repository root. The first pnpm install creates `pnpm-lock.yaml`.
Commit that file with dependency changes. Use `pnpm install --frozen-lockfile` for later installs that must keep the resolved versions.

`pnpm-workspace.yaml` holds separate catalogs for `library`, `vanilla`, `react`, `angular`, `console-only`, `mf-host`, `mf-blotter` and `mf-ticket`.
Each manifest uses its named catalog for external dependencies.
The consumer playgrounds use `workspace:*` for the local library. The vanilla playground loads the library source.
Change versions in the relevant catalog, then run `pnpm install`.

Dependency versions use the current stable releases checked on 2026-11-07.
TypeScript uses 6.0.3 because Angular 22 and typescript-eslint require TypeScript below 6.1.
The workspace enables install scripts for `@parcel/watcher`, `esbuild`, `fsevents`, `lmdb` and `msgpackr-extract`.

```bash
pnpm install
pnpm run dev      # Playground, mock ingest server and iframe host
pnpm run verify   # Format check, typecheck, build, lint, peer, size, dev-server and consumer checks, tests
```

These release checks are not part of `verify`. Run them before a release.

```bash
pnpm run test:e2e        # Browser tests in Chromium, Firefox and WebKit. See e2e/README.md.
pnpm run test:collector  # Sends records to a pinned OpenTelemetry Collector. See e2e/collector/README.md.
pnpm run bench:release   # Latency, throughput, heap, outage and replay checks. See docs/performance.md.
```

- Vanilla playground: `http://localhost:5173/playground/vanilla/index.html`. Add `?worker=1` to send through the transport worker.
- Mock ingest server: `http://localhost:8787`. It accepts `/v1/logs`, `/v1/metrics`, `/v1/traces` and `/v1/replay`. It prints one line for each record, metric point, span and replay segment.
- Cross-origin child frame: `http://localhost:5174`. The vanilla playground registers it and its same-origin child frame before they load.
- The React example sends its counter, histogram and HTTP duration points to `/v1/metrics`.
- After a build, run `node bin/uiobs.mjs doctor http://localhost:8787/v1/logs --origin http://localhost:5173` to test the command line tool on the mock server.

After dependency changes, run these checks:

```bash
pnpm run lint:fix
pnpm run format
pnpm run verify
pnpm --filter './playground/**' --if-present run build
```

`verify` checks the library. The last command builds each consumer playground that has a build script.
Check the vanilla frames, React and Angular in a browser before a release.
To clear the React dependency cache, run `pnpm --filter @example/react run dev --force`.
